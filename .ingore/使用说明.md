# 使用说明 - Kaguya Mod 逆向工程项目

## 📋 项目概述

本项目旨在将 **五つの難題MOD+ ver2.90.1-1.7.10** 从 Forge 1.7.10 版本逆向工程并分析移植到 Forge 1.20.1 的可行性。

## 🗂️ 项目结构

```
E:\git\kaguya-mod-reborn-by-ai\
├── 五つの難題MOD+ ver2.90.1-1.7.10.jar  # 原始 Mod 文件
├── 
├── 📁 工具脚本
│   ├── decompile_auto.ps1              # 自动反编译脚本（推荐）
│   ├── extract_jar.ps1                 # JAR 提取脚本
│   ├── analyze_feasibility.py          # 可行性分析脚本
│   ├── generate_report.py              # 报告生成脚本
│   ├── run_full_analysis.bat           # 一键运行全流程
│   └── run_extract_ps.bat              # 运行提取脚本
│
├── 📁 输出目录（运行后生成）
│   ├── extracted/                      # 提取的 JAR 内容
│   ├── code/                          # 反编译的源代码
│   ├── feasibility_analysis.json      # JSON 格式分析数据
│   ├── FEASIBILITY_REPORT.md          # 可行性分析报告
│   └── MIGRATION_PLAN.md              # 移植任务书
│
└── 📁 文档
    ├── README.md                       # 项目说明
    ├── DECOMPILE_GUIDE.md             # 反编译指南
    └── 使用说明.md                     # 本文件
```

## 🚀 快速开始

### 方法 1: 一键运行全流程（最简单）

1. 双击运行 `run_full_analysis.bat`
2. 等待自动完成以下步骤：
   - 下载 CFR 反编译器
   - 提取和反编译 JAR 文件
   - 分析源代码
   - 生成可行性报告
3. 查看生成的报告文件

### 方法 2: 分步执行

#### 步骤 1: 反编译 JAR 文件

**选项 A - 使用 PowerShell（推荐）:**
```powershell
# 右键点击 decompile_auto.ps1 -> "使用 PowerShell 运行"
# 或在 PowerShell 中执行：
powershell -ExecutionPolicy Bypass -File decompile_auto.ps1
```

**选项 B - 使用 Python:**
```bash
python extract.py
```

**选项 C - 手动使用 IntelliJ IDEA:**
1. 打开 IntelliJ IDEA
2. File → Open → 选择 JAR 文件
3. IDEA 会自动反编译
4. 导出源代码到 `code/` 目录

#### 步骤 2: 分析可行性

```bash
python analyze_feasibility.py
```

这将生成 `feasibility_analysis.json` 文件，包含详细的分析数据。

#### 步骤 3: 生成报告

```bash
python generate_report.py
```

这将生成：
- `FEASIBILITY_REPORT.md` - 可行性分析报告
- `MIGRATION_PLAN.md` - 移植任务书（如果可行）

## 📊 报告说明

### FEASIBILITY_REPORT.md - 可行性分析报告

包含以下内容：

1. **Mod 基本信息**
   - Mod 名称、ID、版本
   - 作者信息
   - 描述

2. **代码规模分析**
   - 源文件数量
   - 代码行数
   - 包结构

3. **API 使用情况**
   - 检测到的 1.7.10 特有 API
   - 使用频率统计
   - 迁移难度评估

4. **兼容性问题分析**
   - 高/中/低严重性问题列表
   - 每个问题的详细说明
   - 影响和工作量评估

5. **移植可行性评估**
   - 难度评分（0-200）
   - 可行性等级（HIGH/MEDIUM/LOW/VERY_LOW）
   - 预计工时

6. **结论和建议**
   - 是否建议移植
   - 行动计划
   - 注意事项

### MIGRATION_PLAN.md - 移植任务书

仅在可行性为 HIGH 或 MEDIUM 时生成，包含：

1. **任务列表**
   - 按阶段分组（准备、核心迁移、测试等）
   - 每个任务的优先级和预计工时
   - 完成标准

2. **详细迁移指南**
   - 环境准备
   - 针对性的代码迁移示例
   - 注册系统、渲染系统等具体指导

3. **测试计划**
   - 单元测试清单
   - 功能测试清单
   - 兼容性测试清单

4. **项目里程碑**
   - 4个主要里程碑
   - 每个里程碑的目标和时间

## 📝 工作流程详解

### 完整流程图

```
1. 原始 JAR 文件
   ↓
2. 提取 JAR 内容 (extract_jar.ps1)
   → extracted/ 目录
   ↓
3. 反编译 .class → .java (decompile_auto.ps1)
   → code/ 目录
   ↓
4. 分析源代码 (analyze_feasibility.py)
   → feasibility_analysis.json
   ↓
5. 生成报告 (generate_report.py)
   → FEASIBILITY_REPORT.md
   → MIGRATION_PLAN.md
   ↓
6. 人工审查报告，决定是否继续
   ↓
7. 如果可行：按照 MIGRATION_PLAN.md 执行移植
```

## ⚠️ 常见问题

### Q1: PowerShell 脚本无法运行

**问题**: 提示"无法加载，因为在此系统上禁止运行脚本"

**解决方案**:
```powershell
# 临时允许脚本执行
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

# 然后运行脚本
.\decompile_auto.ps1
```

### Q2: Python 脚本报错 "No module named 'xxx'"

**解决方案**:
所有脚本只使用 Python 标准库，不需要额外安装模块。如果仍然报错，请确认 Python 版本为 3.7+。

### Q3: CFR 下载失败

**解决方案**:
手动下载 CFR:
1. 访问 https://github.com/leibnitz27/cfr/releases/latest
2. 下载 `cfr-X.XXX.jar`
3. 重命名为 `cfr.jar` 并放在项目根目录

### Q4: 反编译后代码无法编译

**说明**:
这是正常的。反编译的代码可能包含：
- 无法推断的泛型
- 不完整的类型信息
- 编译器生成的特殊代码

**建议**:
- 将反编译代码作为参考，而不是直接使用
- 理解逻辑后重新编写

### Q5: 生成的报告显示"无法检测 API 使用"

**原因**: `code/` 目录为空或未成功反编译

**解决方案**:
1. 确认步骤 1（反编译）已成功完成
2. 检查 `code/` 目录是否包含 `.java` 文件
3. 如果没有，尝试手动反编译（使用 IntelliJ IDEA）

## 📖 下一步行动

### 如果报告显示"可行性: HIGH"

1. ✅ 阅读 `MIGRATION_PLAN.md`
2. ✅ 设置 Forge 1.20.1 开发环境
3. ✅ 创建新的 Mod 项目
4. ✅ 按照任务书逐步迁移
5. ✅ 每完成一个模块就测试

### 如果报告显示"可行性: MEDIUM"

1. ⚠️ 评估是否有足够的时间和资源
2. ⚠️ 考虑寻找团队成员协助
3. ⚠️ 制定详细的时间计划
4. ⚠️ 准备好应对挑战

### 如果报告显示"可行性: LOW" 或 "VERY_LOW"

1. ❌ 重新评估是否值得移植
2. ❌ 考虑开发一个新的替代品
3. ❌ 或者作为长期项目（数月）规划
