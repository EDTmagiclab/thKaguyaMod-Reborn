**成果**：符卡系统框架核心迁移完成，`./gradlew build` 通过（jar 255KB）。

### 迁移的类
- `EntitySpellCardCircle`（魔法阵，264 行）：符卡发动时的魔法阵效果。继承 Entity，同步数据（circleSize/circleType/endTime/animationCount），跟随 user，到时间消失。

- `SpellCardRegistry`（注册表，262 行）：纯数据 Map + registerSpellCard/getSpellCardClass，`newInstance()` → `getDeclaredConstructor().newInstance()`（Java 17）。
- `EntitySpellCard`（符卡实体，343 行）：符卡生命周期，构造函数通过 SpellCardRegistry 实例化 THSpellCard，tick 调用 useSpellCard.onUpdate()，到时间 finish。裁剪 danmakuRemove（弹消）。
- `THKaguyaLib`（符卡宣言，518 行裁剪版）：只保留 spellCardDeclaration 核心（创建 EntitySpellCard）+ radTrans/degTrans。裁剪 itemEffectFollowUser/itemEffectFinish/createSilverKnife/getPlayerPower/danmakuRemove。

- 渲染：RenderSpellCardCircle + RenderSpellCard（占位，阶段 4 补完整）

### 符卡系统工作机制（重要理解）
boss（EntityDanmakuMob 子类）→ THKaguyaLib.spellCardDeclaration → EntitySpellCard（符卡实体）+ THSpellCard（符卡逻辑）→ 每 tick spellcard_main() 生成弹幕。魔法阵 EntitySpellCardCircle 是符卡视觉效果。

### 激光 shotId 编码（关键）
- shotId = form*8 + color（LaserData 里 form 字段，或 color 直接 ≥8 时由单 form 重载传入）

### 实现
- **普通激光**：梭形圆柱体（13 段、8 边形截面、cos 宽度两头尖中间粗），白色核心（entityCutoutNoCull 不透明）+ 彩色外层（entityTranslucent 半透明 1.2 倍，原版加色混合退化）
- **MasterSpark**：单边锥形（sin 宽度从 0 增大到 maxWidth=width*1.6），白色核心 16 边形 + 彩虹外层 64 边形（sin/cos 循环 + width 波动）

- **Gungnir/Laevateinn**：物品触发（ItemSpearTheGungnir/ItemLaevateinn 未迁移），专属顶点模型（29/53 顶点 + 24/44 面）留阶段 4-6，兜底普通激光

### 关键坑（务必遵守）
- **激光朝向**：`mulPose(YP.rotationDegrees(yaw))` + `mulPose(XP.rotationDegrees(-entity.getXRot()))`，然后激光沿 +Z 延伸。与 RenderTHShot.renderArrowShot 的朝向变换完全一致（yaw=render 参数，pitch=entity.getXRot()）
- **RenderType**：双面半透明用 `entityTranslucent(res)`（单参数=no cull）；双面 cutout 用 `entityCutoutNoCull`。激光原版禁用 cull，故用双面版本避免 winding 错误
- **普通激光是梭形（两头尖）不是单边锥**：cos 宽度 angle 从 -π/2→π/2；MasterSpark 才是单边锥（sin 宽度 0→maxWidth）。别搞混
- **激光起点偏移**：普通激光 zStart=0.1*length（原版 centerZ1-centerZ2），MasterSpark 从 0 开始
- 顶点染色：8 色表 COLOR_R/G/B 与 RenderTHShot 完全一致；彩虹色 sin/cos 负值要 clamp 到 0 再乘 255（原版 GL 自动 clamp）

## 改造 gen_models.py 支持数组式 item 模型（未转换）

用户要求"先改造脚本、先别转换"，已完成脚本改造并用 dry-run 验证（未生成任何 .java）。

**新增能力**（向后兼容，living 模型 ModelTHFairy 验证不受影响）：
1. **数组式**：`xxx = new ModelRenderer[N]; xxx[i] = new ModelRenderer(...)` → 展开成 `xxx_i` 独立部件
2. **for 循环展开**：循环变量代入 + 循环内变量累加（`angle += pi8`），经 Python eval 实际求值
3. **rotateAngleX/Y/Z 赋值**：`xxx.rotateAngleX = ((float)Math.PI/2F)` → rot 三元组（弧度）
4. **表达式求值**：`(float)/(double)` 转换、Math.PI、MathHelper.cos/sin、float 后缀 F/f、MathHelper→math 求值成数字
5. **嵌套括号提取**：setRotationPoint 参数含 `MathHelper.cos(...)` 嵌套括号，改用括号平衡 extract_args + split_args（顶层逗号），修复 `[^)]+` 截断 bug

**关键坑**：setRotationPoint/addBox 参数可能含 `cos(...)/sin(...)` 嵌套括号，`[^)]+` 正则会在第一个 `)` 截断 → 必须用括号计数提取。

**用法**：
- dry-run（默认）：`python tools/gen_models.py <ModelXxx.java>` 打印解析结果
- 写出 item 静态模型：`--write <out.java>`（默认泛型 <T extends Entity>，无动画）
- 写出 living 动画模型：`--write <out.java> --mob`（<T extends EntityDanmakuMob> + setupAnim）

**已验证 7 个模型解析正确**：Hisou（数组逐元素）/Kinkakuzi（rotateAngleX）/YuukaParasol（数组+循环+MathHelper+rotateAngleX）/MiniHakkero2（循环+rotateAngleZ+angle累加）/PrivateSquare（rotateAngleX）/CursedDecoyDoll（标准Techne）/THFairy（向后兼容）。
