PHASE 082026-10-18 · 收尾

复核轮：246 条差异，和三个真因

最后一天不再加功能，而是逐条比对 1.7.10 的行为。大部分差异一句话就能解释，只有三个根因藏得很深。

  • 真因一：EntityType 由构造器决定。子类的便利构造器把类型写死成 TH_SHOT，客户端就按普通弹实例化——梦想封印永远是 5 颗默认红弹，专用渲染器一次都没被调用
  • 真因二：透明像素是红的。1.7.10 靠 GL_ALPHA_TEST 丢掉 alpha=0 的像素，现代混合直接加算 → 整片红 / 橙方块
  • 真因三：getUseItem() 不是手持物。松手瞬间返回 EMPTY，「还拿着制御棒吗」必判错 → 核弹在手里自爆
  • 顺带复活原作者注释掉的万宝槌改造台，做成可开关的实验性玩法 + 一个成就

Post-mortem

六个把时间烧掉的坑

这些不是「写错了一个方法」，而是两个版本的运行模型不同，导致「照抄源码」必然失败的地方。

01 / ENTITY TYPE

实体的类型由构造器决定，而不是由类决定

1.20.1 的客户端拿到网络包里的类型 id，用注册表里的工厂新建一个实体——它不会知道你原本 new 的是子类。便利构造器若把类型写死成基类，子类的渲染器、同步数据、碰撞箱全部失效。

4 个子类改为传入自己的 EntityType，梦想封印与核弹立刻恢复正常。
02 / ALPHA

1.7.10 贴图的透明像素是红色的

老贴图把背景涂成 (255,0,0,0)，靠 alpha test 丢弃。现代混合模式不看 alpha 通道，那些像素被当成纯红加了上去——于是「梦想封印」变成一个红方块。

新增 cutout + 自定义混合的 RenderType，恢复 alpha test 语义。
03 / REGISTRY

不能在运行期 new Item

原版 1.7.10 允许随手 new ItemXxx() 当数据载体用。1.20.1 的注册表在启动后就冻结，运行期 new 出来的物品没有 id、没有贴图，还会让分发逻辑静默失败。

改为引用已注册的 Item 单例；空 catch 是当时最大的帮凶。
04 / CULLING

面向相机的 quad 必须关掉背面剔除

billboard 的顶点绕序取决于相机位置，一半视角下面朝相机的那面是「背面」，被 GPU 直接丢掉。表现是「某些角度完全看不见」。

所有 billboard 一律改用 NoCull 的 RenderType，成为一条硬性不变量。
05 / ITEM USE

getUseItem() ≠ 手上拿的东西

getUseItem() 只在「正在使用」期间有值。松手那一刻它已经是 EMPTY，用它判断「玩家还拿着制御棒吗」永远为假——核弹于是在手里炸了。

改用 getMainHandItem()，与原版 inventory.getCurrentItem() 对齐。
06 / VEHICLE

服务端不要驱动玩家操控的载具

扫帚上玩家一直「moved wrongly」并被拽回原位：服务端每 tick 自行给它一个速度，和客户端输入打架。WASD 读键分支又因为一个 isEmpty 判断从未进入。

客户端负责输入、服务端只做校验；控制分支改用 getControllingPassenger。

Forge 模组列表里的 Config → 实验性玩法，可单独开关；首次开启会弹一次警告页，可勾选「不再提示」。配置由服务端判定，多人服需要管理员开启。

Known issues

公测版的诚实清单

功能覆盖完整，但与 1.7.10 仍存在一批行为 / 数值差异。完整清单见 差异复核报告（12 章，246 条）。

仍存在的差异

  • 弹幕会命中动物与村民
  • 贴墙目标可能免伤
  • 追踪弹比原版更「咬人」
  • 固定激光被方块挡住后会永久变短
  • 激光撞弹会直接消除对方（原版互相削伤害）
  • 灵梦 / 咲夜 / 神子暂不掉落 power / point 素材
  • 时停不冻结弹幕生物

有意为之的改动

  • Boss 血条改用 1.20.1 的 ServerBossEvent
  • 自然生成改为 biome_modifier + 配置门控
  • 2026-10-18 收尾轮已修：弹幕素材配方产量、双扇蓄力方向、工具耐久
